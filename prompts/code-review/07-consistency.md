## 规范一致性检查规则（Consistency）

### 重点检查

- 代码风格与工程规范
  - 是否遵循项目既有 lint/format 规则；是否引入不一致写法
  - 目录结构是否与现有模块一致；命名是否符合惯例
- 日志/指标/追踪一致性
  - 日志级别与字段是否统一；错误是否带足够上下文
  - 指标命名/标签是否规范；避免高基数标签
- 配置与开关
  - 配置项命名、默认值与校验是否一致
  - feature flag 是否可控、可回滚、默认安全
- 错误码与返回结构
  - API 返回结构、错误码语义、HTTP 状态码使用是否一致

### 常见高风险信号

- 新增“私有规范”导致团队维护成本上升
- 指标/日志标签包含用户输入导致高基数与成本飙升
- 配置缺少校验导致线上不可控行为

### 需要给出的证据

- 与现有约定冲突的具体点（文件/接口/字段）
- 可能的运维/观测成本影响

### 建议输出应包含

- 修复策略：统一规范、收敛字段、补校验、补回滚与默认安全策略
- 验证建议：lint/format、契约测试、接口回归
