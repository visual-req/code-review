## 可维护性与可读性检查规则（Maintainability）

### 重点检查

- 模块边界与职责
  - 单一职责；层次划分（API/Service/DAO）是否清晰
  - 业务规则是否集中；避免散落的“魔法条件”
- API 与契约
  - 参数/返回值语义是否明确；错误契约是否一致
  - 兼容性：变更是否会破坏调用方；是否需要版本化
- 重复与抽象
  - 重复代码是否可收敛；抽象是否过度/过早
- 可读性
  - 命名是否表达意图；复杂逻辑是否可拆分为可测单元

### 常见高风险信号

- 巨型函数/巨型类；多层嵌套 if/else
- 同一业务规则在多处以不同形式实现
- 关键流程缺少清晰的错误路径与返回语义

### 需要给出的证据

- 具体的重复点/耦合点位置
- 变更扩散范围（改一处需要改多少处）

### 建议输出应包含

- 修复策略：提炼函数/模块化、收敛契约、减少耦合、统一错误模型
- 验证建议：新增回归测试覆盖重构边界，确保行为不变
