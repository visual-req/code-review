## 安全检查规则（Security）

### 重点检查

- 输入处理与注入面
  - SQL/NoSQL/LDAP 注入：拼接查询、动态字段、未参数化
  - 模板注入：服务端模板表达式、未转义输出
  - 命令注入：shell 执行、system/exec、参数拼接
  - 路径穿越：用户可控路径、解压/读取/写入文件
  - 反序列化风险：不可信数据反序列化、对象多态
  - XXE/SSRF：XML 解析、URL fetch、内网探测
- 鉴权与授权
  - 认证：会话/Token 校验、过期、撤销、刷新、签名验证
  - 授权：对象级授权（IDOR）、租户隔离、RBAC/ABAC 校验位置
- 敏感信息与日志
  - 密钥/Token/PII 是否硬编码、回显、写入日志或错误信息
  - 日志与追踪是否脱敏；是否包含请求体/凭证
- 依赖与供应链
  - 锁文件是否存在；依赖版本漂移；已知漏洞（CVE）暴露面

### 常见高风险信号

- “仅前端校验”或“相信网关/上游已经校验”
- 用字符串拼接构造查询/命令/路径/URL
- 授权检查分散且不一致，或仅在 UI 层做限制
- 自定义加密/签名实现，或跳过证书/签名验证

### 凭证与敏感信息处理（强制）

- 送审前先做密钥/凭证预过滤与最小化，只读评审所需的源代码、配置与依赖清单；模型侧声明「不落库（no-store）」
- 报告中疑似真实凭证一律掩码：前 4 位 + `***` + 后 2 位；**严禁完整输出**；攻击载荷示例不得含真实密钥
- 一旦发现疑似真实凭证，须先口头告知用户「该凭证疑似已泄露，请立即轮换」，并纳入轮换流程
- 优先在受信任的内网/私有化模型环境运行；若使用外部公有模型，须先脱敏并明示外泄风险

### 需要给出的证据

- 不可信输入来源 → 危险 sink 的数据流路径
- 缺失的鉴权/鉴权绕过点（端点、handler、service 方法）
- 可能的攻击载荷示例（最小化，不要包含真实密钥）

### 建议输出应包含

- 修复策略：参数化/白名单/编码与转义/最小权限/集中鉴权
- 验证建议：安全单测、渗透复现步骤、依赖升级与锁定策略
